# KV存储
本项目是一个基于**RESP协议**的键值存储系统，底层使用**NtyCo协程**实现高并发网络处理。系统通过 **io_uring** 完成异步增量日志（add.txt）与全量快照（full.txt）持久化，并借助 **eBPF uprobe** 实时捕获写命令，实现实时数据同步。结合 **RDMA** 实现持久化数据同步。此外，项目内置内存池管理动态内存，也可使用glibc提供的回收函数回收部分内存，还可接入 **jemalloc** 提升分配性能。

## 编译
### 1.生成 32 字节(256-bit)的随机安全密钥
在启动服务前，请确保 `config` 目录存在，并生成用于快照防篡改的 HMAC 密钥:

```bash
head -c 32 /dev/urandom > config/hmac.key
```
### 2.下载NtyCo源码
Ntyco协程代码作为子模块加入进来，所以需要通过以下命令进行下载:

```bash
git submodule update --init
```
### 3. 配置项
注：配置文件中 `1` 代表开，`0` 代表关
#### 主节点
| 配置项 | 含义 | 示例 |
|--------|------|------|
| `ip` | 主节点 IP，根据实际环境修改 | `192.168.159.137` |
| `port` | 服务监听端口 | `2000` |
| `show_response` | 是否回发 `+OK` 等响应 | `1` |
| `use_mempool` | 是否使用内存池 | `1` |
#### 子节点
| 配置项 | 含义 | 示例 |
|--------|------|--------|
| `sync_ip` | 子节点 IP，根据实际环境修改 | `192.168.159.129` |
#### 功能
| 配置项 | 含义 | 可选值 |
|--------|------|--------|
| `full_save` | 是否启用全量持久化落盘 | `0` / `1` |
| `add_save` | 是否启用增量持久化落盘 | `0` / `1` |
| `storage_structure` | 存储结构 | `hash` / `array` / `skiplist` |

### 内存
| 内存 | 启动 | 插入10万条数据峰值 | 删除对应10万条数据完成 | 
|------|-----|-------------------|----------------------|
| malloc | 虚拟 93792 / 物理 10648 | 虚拟 101M / 物理 20480 | 虚拟 94668 / 物理 10800 |
| 内存池 | 虚拟 93792 / 物理 10652 | 虚拟 99M / 物理 19208 | 虚拟 94076 / 物理 10920 |
| jemalloc | 虚拟 205M / 物理 11172 | 虚拟 214M / 物理 19664 | 虚拟 218M / 物理 11448 | 
**注 1（malloc）：验证无内存残留**
- 暖身后（峰值）：Rss = 24012 kB，Anonymous = 20480 kB
- 删除完成后：Rss = 14408 kB，Anonymous = 10876 kB
- 结论：第 1 轮暖身后，再插入和删除同等数据量，不会再有一次性开销。测试经过四轮，均无内存残留。

**注 2（内存池）：验证无内存残留**
- 暖身后（峰值）：Rss = 22612 kB，Anonymous = 19220 kB
- 删除完成后：Rss = 14312 kB，Anonymous = 10920 kB
- 结论：第 1 轮暖身后，再插入和删除同等数据量，不会再有一次性开销。测试经过四轮，均无内存残留。

**注 3（jemalloc）：验证无内存残留**
- 暖身后（峰值）：Rss = 24980 kB，Anonymous = 19676 kB
- 删除完成后：Rss = 16744 kB，Anonymous = 11440 kB
- 结论：第 1 轮暖身后，再插入和删除同等数据量，不会再有一次性开销。测试经过四轮，均无内存残留。
#### 物理内存未回收部分
| 内存 | 未回收 | 构成 | 回收率 |
|------|-------|------|-------|
| malloc | +152kB | 全部是 glibc heap 中已 free 但未归还的空间 | 98.5% |
| 内存池 | +268kB | 备用 chunk 64 kB(刻意保留，避免反复 mmap/munmap)，加上 glibc heap 中已 free 但未归还的空间 204 kB。heap 中实际在用只有 45 kB | 96.9% |
| jemalloc | +276kB | 全部在匿名 mmap：jemalloc 的元数据（主要是 edata）。jemalloc 不会归还这部分 | 96.7% |
