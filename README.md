# KV存储
本项目是一个基于**RESP协议**的键值存储系统，底层使用**NtyCo协程**实现高并发网络处理。系统通过 **io_uring** 完成异步增量日志（add.txt）与全量快照（full.txt）持久化，并借助 **eBPF uprobe** 实时捕获写命令，实现实时数据同步。结合 **RDMA** 实现持久化数据同步。此外，项目内置内存池管理动态内存，也可使用glibc提供的回收函数回收部分内存，还可接入 **jemalloc** 提升分配性能。

## 编译
### 1. 编译 eBPF 程序
由于 uprobe 需要挂载到可执行文件的绝对路径上，而路径因机器而异，
编译前需要把 `resp_capture.bpf.c` 里的路径改成你本机的实际路径。
**步骤：**
1. 查询 kvstore 目录的绝对路径：
   ```bash
   pwd
   # 例如输出：/home/samba/kvstore
   ```
2. 进入 eBPF 源码目录：
    ```bash
    cd libbpf-bootstrap/examples/c/
    ```
3. 编辑 resp_capture.bpf.c，找到SEC("uprobe/...")这一行，把路径替换成你上一步查到的实际路径：
    ```c
    // 修改前
    SEC("uprobe//home/samba/kvstore/kvstore:kvs_split_token")

    // 修改后（替换成你自己的路径）
    SEC("uprobe//your/path/to/kvstore/kvstore:kvs_split_token")
    ```
4. 编译 eBPF 程序
    ```bash
    make
    # 编译成功后会生成 .output/resp_capture.bpf.o 和 .output/resp_capture.skel.h
    ```
5. 返回项目根目录

### 2. 配置项
注：配置文件中 `1` 代表开，`0` 代表关
#### 主节点
| 配置项 | 含义 | 示例 |
|--------|------|------|
| `ip` | 主节点 IP，根据实际环境修改 | `192.168.159.137` |
| `port` | 服务监听端口 | `2000` |
| `show_response` | 是否回发 `+OK` 等响应 | `1` |
| `use_mempool` | 是否使用内存池 | `1` |
#### 子节点
| 配置项 | 含义 | 示例 |
|--------|------|--------|
| `sync_ip` | 子节点 IP，根据实际环境修改 | `192.168.159.129` |
#### 功能
| 配置项 | 含义 | 可选值 |
|--------|------|--------|
| `full_save` | 是否启用全量持久化落盘 | `0` / `1` |
| `add_save` | 是否启用增量持久化落盘 | `0` / `1` |
| `storage_structure` | 存储结构 | `hash` / `array` / `skiplist` |
### 3. 编译目标文件
| 目标 | 说明 | 编译命令 |
|------|------|---------|
| 主节点 | kvstore | `make` |
| 子节点 | kvstore_slave | `make server_slave` |
| 增量存储测试 | testcase_add |	`make testcase_add` |
| 全量存储测试 | testcase_full | `make testcase_full` |
| 增量+全量测试 | testcase_save | `make testcase_save` |
| slave 同步测试 | testcase_slave |	`make testcase_slave` |
   
## 运行
主节点因为采用了ebpf，所以需要用管理员权限。子节点不需要管理员权限
### 启动主节点
```bash
sudo ./kvstore
```
### 启动子节点
```bash
./kvstore_slave
```
